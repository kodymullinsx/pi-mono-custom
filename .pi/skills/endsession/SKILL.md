# End Session Retrospective

Run all three phases in sequence. All updates are autonomous — apply changes directly to memory, skills, and AGENTS.md without seeking approval.

Pi-specific notes:
- Instruction file is `AGENTS.md` (not CLAUDE.md) — global at `~/.pi/agent/AGENTS.md`, project-level in repo root
- No native plan mode or background jobs in Pi — use `todo` tool for task tracking
- Memory routing is automatic via the `domain-memory` extension (same CWD logic as Claude)
- `_index.md` is auto-regenerated by the extension when `memory.md` is written — no manual regen needed

---

## Phase 1 — Memory Update

**Delegate to memory-creator skill.**

Scan the session for memory-worthy content (new facts, project state changes, decisions, corrections, contacts, deadlines). Then invoke the memory-creator skill with context about what changed.

The memory-creator skill handles:
- Routing to correct tree (`~/projects/Memory/` vs `~/work/Memory/`)
- Reading existing domains and applying autonomous edits
- Organizing content across memory.md and references/
- Updating last_updated and syncing _index.md

The `domain-memory` extension auto-regenerates `_index.md` on memory.md writes — no manual regen needed in interactive sessions.

### Two tiers of memory output

**Stable facts → `memory.md` directly** (current behavior). Use when the fact is confirmed and unlikely to change before the next Dream cycle.

**Session context → `_notes.md`** (append-only, per-domain). Use when content is real but session-specific, in-progress, or not yet stable enough for permanent inclusion. Dream reads `_notes.md` alongside `memory.md` during its weekly `review-domain` pass and promotes relevant content — then clears the file.

Format for `_notes.md` entries:
```markdown
<!-- YYYY-MM-DD session note -->
- [observation or context fragment]
```

When in doubt between the two tiers: if the fact would still be true and useful in a week, write it to `memory.md`. If it might be superseded by then, write it to `_notes.md`.

See: `memory-creator` skill at `~/.pi/agent/skills/memory-creator/SKILL.md` for full procedures.

## Phase 2 — Skill & Feedback Capture

**Step 1: Identify correction patterns**

Scan the session for moments where:
- User corrected your approach ("no", "don't", "wait", "actually", "stop", "not like that")
- User explicitly validated a non-obvious choice ("yes exactly", "perfect", "keep doing that")
- You made the same mistake twice
- A surprising approach turned out to be right

**Step 2: Determine scope**

For each pattern, decide:
- **Behavioral rule** → add to `~/.pi/agent/AGENTS.md` or auto-memory
- **Skill-specific** → update that skill's SKILL.md at `~/.pi/agent/skills/<name>/SKILL.md`
- **New skill warranted** → flag for user confirmation (don't create unilaterally)

**Step 3: Apply changes directly**

Write the specific rule/edit to the appropriate file. For new skills, create the skill directory and SKILL.md.

See: `skill-creator` skill at `~/.pi/agent/skills/skill-creator/SKILL.md` for creating/updating skills.

---

## Phase 3 — AGENTS.md Review

**Scan for structural gaps:** Check for friction pointing to missing or wrong instructions:
- Workflow rules that were forgotten or misapplied
- Tool preferences not yet codified
- Constraints that came up multiple times (provider role compatibility, extension availability, etc.)
- Pi-specific nuances that should be documented globally

**Apply targeted edits:** Make targeted insertions only; no restructuring. Write changes directly.

Read `~/.pi/agent/AGENTS.md` for context before editing.

---

## Todo Hygiene Check

Before declaring the session complete, review current todos owned in the session and clean up any that are stale:
- mark resolved work `completed`
- release items you are no longer actively owning
- do not leave finished or superseded work in `pending` / `in_progress`

If a todo remains open at session end, explicitly state why it is still open.

## Completion

After all three phases, summarize in 3–5 bullet points what was updated across memory, skills, AGENTS.md, and todo cleanup. Confirm session is ready to close.
